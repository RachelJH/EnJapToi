# 현재 후원 효과 규칙

`feature/observe-payamount`, 2026-11-02. 이 문서가 이전 리뷰·README 변경 기록의 효과/가격/명령어 설명보다 우선합니다.

| 치즈 | 효과 |
|---|---|
| 1,000 | 버프, 안전 랜덤 이동, 빵 5개, 잔여 내구도 1 다이아몬드 곡괭이 각각 25% |
| 2,000 | 디버프 6종 중 하나, 30초 |
| 3,000 | 현재 X/Z의 안전한 지표면 이동 |
| 4,000 | 15% 사망, 85% 생존. 생존도 정상 완료 및 후원 알림 대상 |
| 5,000 | 비어 있지 않은 슬롯 하나의 전체 스택 삭제. 갑옷·보조 손 포함 |
| 30,000 | 확정 사망 |

버프는 신속·힘·재생·저항·점프 강화·성급함 중 하나를 60초간 부여합니다. 디버프는 구속·나약함·채굴 피로·실명·허기·멀미 중 하나입니다. 모두 레벨 I입니다. 메시지 내용으로 효과를 선택할 수 없으며 `!몹`을 포함한 이전 명령어도 일반 문자열로 취급합니다. 몬스터 소환 코드는 제거했습니다. 운영자 `/ejt test <event>`는 유지하지만 `mob`는 실패로 종료됩니다.

랜덤 이동은 같은 월드의 로드된 청크에서 수평 반경 50블록 이내의 안전 지점을 찾습니다. 지표면 이동은 현재 소수점 X/Z를 보존하고 오버월드 최상단을 검사합니다. 위험한 지점, 안전 지점 없음, 다른 차원, 이동 취소는 기존 정책대로 실패합니다. 빈 인벤토리 삭제, 취소된 사망·포션, 일부 아이템 지급 실패에는 성공 알림이 없습니다.

## 대기열 호환성

기존 이벤트의 ID·효과·치즈 등급을 재추첨하거나 일괄 변경·삭제하지 않습니다. 과거 5,000치즈 `surface`/`chancekill`은 그대로 실행하고 기존 금액으로 알립니다. 과거 `mob`는 실행 함수를 호출하지 않고 알림 없이 종료합니다. Paper의 `DONE`은 처리 종료만 뜻하며 성공 판정은 false입니다. 실패한 효과에도 사용하던 기존 상태 의미를 유지합니다. Python의 이전 모의 outbox는 몬스터 항목을 `retired`로 보존하며 `done`으로 집계하지 않습니다. 관찰 모드에서는 이전 outbox도 소비하지 않습니다.

SQLite FIFO, 같은 ID 중복 방지, 오프라인·사망·리스폰 대기, 기본 `interval-ticks: 60`(3초), 실행 불확실 상태 보류, 완료 저장 이후 후원자 알림을 유지합니다. 실패를 자동 재실행하지 않으며 월드와 SQLite 사이의 원자성 한계도 유지됩니다.

## 관찰 모드와 검증

`payAmount`는 원화 문자열입니다. 치즈 환산을 가정하지 않습니다. `receiver.enable-game-delivery: false`를 유지하고 실제 금액 매핑·검증 파일은 생성·변경하지 않습니다. `tests/fixtures`는 가상 데이터 전용이며 운영 매핑의 근거가 아닙니다.

### 외부 운영 매핑 설정

운영 매핑은 `receiver.amount-map`이 가리키는 **외부 JSON 파일**입니다. 기본 경로는 `C:/EnJapToi/bridge/.local/amount-map.json`이며 실제 설치 경로에 맞춥니다. 검사용 `amount_check.py`와 별개로, 실제 수신기가 시작할 때 `amount_mapping.py`로 이 파일을 읽습니다. 이전 JSON 형식과 채널·매핑 해시에 묶인 승인 검사는 유지합니다.

배포 ZIP의 `bridge/amount-map.example.json`은 다음과 같은 빈 템플릿입니다.

```json
{}
```

JSON 객체의 **키는 실관측으로 확인한 원화 `payAmount` 숫자 문자열**, **값은 연결할 치즈 등급 정수**입니다. 값은 `1000`, `2000`, `3000`, `4000`, `5000`, `30000`만 허용합니다. 미확인 원화 키는 추가하지 않습니다. 동일한 숫자나 일정 비율이라는 가정으로 6개 키를 채우지 않습니다. `{}` 또는 등록되지 않은 금액은 게임 효과를 선택하지 않습니다. 등록된 항목도 `enable-game-delivery: false`에서는 효과를 선택·전달하지 않습니다.

최초 설치 시 템플릿을 `.local/amount-map.json`으로 복사하되 기존 파일이 있으면 덮어쓰지 않습니다. 템플릿에는 인증정보나 실금액 대응이 없으며 `.local`의 실제 운영 파일은 Git·배포 ZIP에서 제외합니다. 새 Python 모듈이 필요하므로 이번 업데이트는 `bridge/*.py`를 함께 배포합니다. 이후 **원화 금액 변경은 외부 JSON 편집만으로 가능**하며 Java/Python 소스 수정이나 JAR 재빌드는 필요하지 않습니다.

검증 규칙:

- 파일 누락·읽기 실패·빈 파일·JSON 오류·UTF-8 오류·64 KiB 초과·과도한 중첩은 수신기 시작을 중단합니다. 빈 파일과 유효한 빈 객체 `{}`는 다릅니다. 기본 매핑으로 대체하거나 일부 항목만 적용하지 않습니다.
- 중복 원화 키는 값이 같거나 JSON 유니코드 이스케이프로 표기돼도 거절합니다. 키는 선행 0 없는 1~12자리 양의 ASCII 정수 문자열만 허용합니다.
- 값 누락·null·문자열·불리언·소수·허용되지 않은 등급, 객체/배열은 거절합니다. 서로 다른 확인된 원화 키가 같은 등급을 가리키는 것은 허용합니다.
- 전체 6등급을 채울 필요는 없습니다. 검증된 항목만 등록하고 나머지는 제외합니다. 같은 키에 여러 등급을 지정할 수는 없습니다.

적용 절차는 **Paper 정상 종료 → 운영 JSON 백업·편집·오프라인 비교 → Paper 재시작**입니다. 수신기는 시작 시점의 매핑 사본을 유지하므로 실행 중 파일 편집은 즉시 반영되지 않습니다. `/ejt reload`만으로 Python 수신기가 다시 시작되지는 않습니다. 이 정책은 처리 도중 매핑이나 승인 범위가 바뀌는 것을 방지합니다. 매핑이 바뀌면 이전 해시의 운영자 확인 파일은 새 매핑에 사용할 수 없습니다. 자동으로 확인 파일을 갱신하지 않으며 이번 작업에서도 생성하지 않습니다.

SQLite에 이미 선택·저장된 이벤트는 새 설정으로 재추첨하거나 삭제하지 않습니다. 이전 Python outbox의 다른 매핑 해시 항목도 기존처럼 보류합니다. OAuth·Paper 접수·중복 방지·후원 알림 경로와 3초 처리 간격은 그대로입니다. **실제 전달은 계속 비활성화합니다.**

### 공식 단위 확인과 실제 관찰 준비 (2026-11-02)

- [CHZZK 공식 Session 명세](https://chzzk.gitbook.io/chzzk/chzzk-api/session)의 DONATION은 `payAmount`를 String, 설명을 `후원 금액 (원)`으로 정의하며 후원 종류는 `CHAT` 또는 `VIDEO`입니다. 치즈 수량 필드나 치즈 수량과 `payAmount` 사이의 환산식은 명시하지 않습니다.
- [공식 채팅 후원 안내](https://help.naver.com/service/30044/contents/22609?lang=ko&osType=COMMONOS)는 후원할 치즈 액수와 추가 유료 보이스 이용료를 구분합니다. 이 안내만으로 API 금액에 보이스 이용료가 포함되는지는 알 수 없습니다. 충전 결제금액, 할인, 세금 또는 스트리머 정산액을 `payAmount` 환산 근거로 사용하지 않습니다.
- 따라서 숫자가 같다는 이유로 1:1 대응이나 다른 비율을 적용하지 않습니다. 6개 등급의 효과 선택은 이미 구현돼 있지만, 실제 원화 키는 각 등급의 관측값이 확인될 때까지 비워 둡니다.

관찰 절차:

1. 친구 PC에서 방송인 계정 OAuth, 채널 ID 일치, `후원 조회`·`유저 정보 조회` 권한, Python 의존성과 Paper 관리 수신기 시작을 확인합니다. 로그에 `공식 후원 구독 확인 완료.`가 나오는지 확인합니다. 별도 수신기 창을 중복 실행하지 않습니다.
2. `receiver.enable-game-delivery: false`, 선택한 `donation-type: CHAT`, 빈 매핑 `{}`를 유지합니다. 기존 매핑이 있으면 덮어쓰지 말고 백업·검토합니다. 확인 파일을 생성하지 않습니다. 관찰 모드는 기존 Paper 대기열 실행을 막는 설정은 아니므로 서버 콘솔에서 `ejt pause`와 `ejt status`로 기존 대기열을 보존한 채 일시정지합니다. DB·월드를 정상 종료 상태에서 백업합니다.
3. 먼저 무료 기본 보이스의 일반 채팅 후원 한 건만 식별 가능한 시간 구간에 시험합니다. 운영자가 승인한 예산 내에서 진행하고 다른 후원이 겹치거나 재연결·중복으로 대응이 모호하면 해당 관측을 확정하지 않습니다. 이 수신 로그에는 후원자·고유 후원 ID가 없으므로 시간 순서만으로 동시 후원을 정확히 연결할 수 없습니다.
4. 후원 화면/사용 내역에서 **실제로 보낸 치즈 수량**을 직접 확인합니다. 충전 구매금액과 구분합니다. 기존 `receiver.log`의 `payAmount=숫자 KRW`에서 숫자만 비교 도구에 입력합니다. 원본 DONATION, 이름, 메시지, 토큰, 브라우저 인증 URL을 수집·복사하지 않습니다. 화면에 표시한 등급은 독립적으로 확인한 값이어야 하며 로그 숫자에서 역산하지 않습니다.
5. 아래 표를 등급별로 별도 확인합니다. 한 등급의 관측으로 다른 등급을 채우거나 단일 사례를 모든 후원 조건으로 일반화하지 않습니다. 30,000치즈도 실제 지출을 수반하므로 자동으로 시험하지 않습니다. 실제 후원은 이번 개발·자동 테스트에서 실행하지 않았습니다.

| 확인할 치즈 수량 | 기대 게임 효과 | 실제 `payAmount` | 반복 관측·후원 조건 |
|---|---|---|---|
| 1,000 | 버프/이동/빵/곡괭이 각각 25% | 미확인 | 미확인 |
| 2,000 | 디버프 | 미확인 | 미확인 |
| 3,000 | 안전 지표면 이동 | 미확인 | 미확인 |
| 4,000 | 15% 사망·85% 생존 | 미확인 | 미확인 |

비교 도구는 네트워크·OAuth·SQLite·효과 추첨·게임 전달 없이 동작합니다. 별도 파일을 저장하지 않으며 로그 숫자, 확인한 치즈 등급, 해당 등급의 효과 후보만 출력합니다. 현재 배포 워크플로의 `bridge/*.py` 복사에 자동 포함됩니다.

```powershell
$observedKrw = Read-Host "receiver.log의 payAmount 숫자만 입력"
$expectedCheese = Read-Host "후원 화면에서 확인한 치즈 등급 입력"
.\.venv\Scripts\python.exe bridge/amount_check.py --pay-amount $observedKrw --expected-cheese $expectedCheese
```

기본 결과는 `UNMAPPED`입니다. **관측값과 치즈 숫자가 같아도 자동 매핑하지 않습니다.** 기존 후보 매핑을 읽기 전용으로 비교할 때만 `--amount-map bridge/.local/amount-map.json`을 덧붙입니다. `MATCH`는 후보 설정과 사용자가 입력한 예상 등급의 일치만 뜻하며 실제 환산 검증 완료나 게임 전달 승인이 아닙니다. `MISMATCH`는 후보가 다른 등급을 가리킨다는 뜻으로 종료 코드 2를 반환합니다. 잘못된 입력/매핑은 원문을 숨기고 종료 코드 1로 중단합니다. `UNMAPPED`/`MATCH`의 종료 코드 0도 검증 완료를 의미하지 않습니다. 어떤 결과에서도 매핑·검증 파일을 만들거나 바꾸지 않습니다.

유료 보이스, VIDEO, 무료/프로모션 치즈 등 다른 조건은 각각 별도로 확인해야 합니다. 현재 매핑은 후원 종류별로 분리되지 않으므로 CHAT 관측만으로 VIDEO까지 활성화하지 않습니다. 같은 `payAmount`가 서로 다른 치즈 등급에서 나오거나 같은 등급의 값이 조건마다 달라지면 현재 단일 매핑만으로 충분하지 않을 수 있습니다. 원인을 확인하거나 공식 API 지원에 개인정보 없는 질문을 보내기 전에는 전달을 켜지 않습니다. 실제 대응이 확인돼도 별도의 운영자 검토·명시적 활성화 전까지 `false`를 유지합니다.

Python: `python -m unittest discover -s tests`에서 101개 중 99개 통과, 2개 건너뜀(Engine.IO 및 선택 Socket.IO 통합 의존성 미설치). 금액 비교 도구와 운영 매핑의 6개 등급·정확한 키 조회·불일치·미설정·입력 검증·파일 비변경·원문 비노출·설정 교체 후 기존 대기열 보존·승인 해시 불일치·잘못된 설정으로 시작 차단을 포함합니다. Windows DPAPI 접근 때문에 전체 테스트는 사용자 권한에서 실행했습니다.

Java: Microsoft OpenJDK 25.0.5.0.2 / Apache Maven 3.9.16에서 `paper-plugin`의 `mvn -B clean package` 빌드가 성공했습니다. Java 테스트 49개가 모두 통과했으며 실패·오류·건너뜀은 0개입니다. 확률 경계·생존 완료 알림·기존 몬스터 종료/재시작·새 등급 HTTP 검증을 포함합니다.

실제 플레이어가 접속한 Paper 서버에서의 효과 실행과 실제 CHZZK 후원 연동은 아직 검증하지 않았습니다. 자동 테스트 통과는 실제 원화/치즈 대응 검증을 뜻하지 않습니다.

배포 시 서버 정상 종료 및 DB 백업 후 새로 빌드·검증한 JAR와 `bridge/bridge.py`, `bridge/receiver.py`를 함께 교체합니다. OAuth·비밀정보·기존 DB는 유지하고 게임 전달을 켜지 않습니다.
